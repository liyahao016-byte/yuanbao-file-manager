## [2026-07-25] 收纳区拖放功能终极打通：QQ 风格中央浮层收纳方案 交付完成！

### 🚀 1. 根因排查：Tauri 底层事件劫持
- **问题根源**：Tauri 框架在操作系统级别拦截了所有 `drag-drop` 事件（含 App 内部 HTML 元素拖拽），导致网页 DOM 的 `onDrop` 永远无法触发，Console 一片死寂。
- **坐标系天坑**：Tauri 返回的 drop 坐标是 macOS **物理像素**（原点在屏幕左下角），而 CSS 使用**逻辑像素**（原点在窗口左上角），DPR=2 的 Retina 屏幕加上 Y 轴反向，导致所有基于坐标框的判定均失效。

### 🚀 2. 终极解决方案：mousemove + 固定中央浮层
- **`mousemove` 实时追踪**：通过 `window.__lastMouseX/Y = e.clientX/Y` 实时记录鼠标位置，`clientX/Y` 永远是 CSS 逻辑像素，完全绕过坐标系转换问题。
- **固定坐标收纳区**：仿照 QQ「松手添加文件」设计，当拖拽开始时在屏幕**底部正中央**弹出 380×220px 的固定浮层，坐标完全固定与鼠标追踪坐标系一致，一举消灭所有坐标不匹配问题。
- **`window.__draggedFile` 信号识别**：拖动开始时写入内存，`tauri://drag-drop` 触发时读取，两个信号同时满足才执行收纳，保证不误触发。

### 📄 3. 视觉体验升级
- 浮层带毛玻璃（backdrop-filter: blur）、弹簧入场动画（`@keyframes dropzone-appear`）
- 鼠标悬停在浮层上方时，实时变色并文字变化为「松手即可放入收纳盒」
