## 第一部分：产品速览（已完成的 docs 通读结论）

### 1.1 一句话定位

一款 **100% 端侧运行**的 AI 桌面文件管理器：以「混合检索 + 线索自证 + 智能聚类」替代传统树状文件夹管理，解决「不好管 / 容易忘 / 查不到 / 怕泄密」四大痛点。

### 1.2 产品五大支柱

| # | 支柱能力 | 核心机制 | 用户价值 |
|:--|:--|:--|:--|
| 1 | **AI 智能聚类** | 4 大格式簇 + 9 大预设场景簇 + 自然语言动态建簇 | 免手工归类，打开即分好 |
| 2 | **混合检索与匹配线索** | BM25/FTS5 + sqlite-vec 向量，RRF 融合重排（k=60） | 搜「求职」出「简历.docx」，且外显命中原因 |
| 3 | **多标签页 + 上下双分屏** | 每屏独立 TabBar，跨目录直接拖拽 | 保护工作上下文，跨目录对比 |
| 4 | **便捷收纳区** | 物理迁移至 `~/.yuanbao_staging` + AI 聚合命名打包 | 跨视图随手收集，一键成包 |
| 5 | **端侧隐私与性能** | 全本地解析/向量/索引，Rust + Tokio 异步 | 零数据上云，毫秒级响应 |

### 1.3 技术栈实况（以代码为准）

| 层次 | 选型 | 备注 |
|:--|:--|:--|
| 桌面外壳 | **Tauri 2.0**（`@tauri-apps/api ^2.11.1`） | 弃 Electron，追求低内存/小体积 |
| 前端 | **React 19.2.7** + Vite 8 + oxlint | ⚠️ 白皮书写 React 18，实际已升 19 |
| 后端 | Rust（lib.rs 2,277 行单体） | 28 个 `#[tauri::command]` |
| 存储 | SQLite + **FTS5** 倒排 + **sqlite-vec** 向量 | 元数据与向量同库 |
| 模型 | Ollama `localhost:11434`：`qwen2.5:32b`（命名）、`bge-m3`（768 维向量） | 外部服务进程，非内置 |
| 文档解析 | `pdf-extract` / `zip`+XML(docx) / `calamine`(xlsx) | 纯 Rust，无 C 依赖 |
| OCR | **macOS Vision.framework**（`mac_ocr.m`） | 零成本零体积，NPU 加速 |
| 命名抽象 | 「半映射半实际」：`virtual_name` 存 SQLite，可选同步落盘 | 保护物理文件不断链 |

### 1.4 六个技术演进阶段（来自 03 路线图）

```
阶段一 底层架构      Tauri(Rust) + SQLite/FTS5
阶段二 AI 管线       Ollama 外部服务 + sqlite-vec 混合检索
阶段三 文档解析      pdf-extract / zip+XML / calamine
阶段四 虚拟抽象层    virtual_name 解耦 + 工程文件全量过滤
阶段五 原生 OCR      Apple Vision.framework
阶段六 收纳盒架构    ⚠️ 决策反复三次（虚拟映射 → 物理迁移 → 独立窗口）
```

> **重点提示**：阶段六是全项目**决策最不稳定**的模块，07-24 / 07-25 两次架构翻转，且**独立窗口方案在当前代码中已消失**（详见第六部分）。

### 层级认知原则

1. **文档不可信任、代码才是事实**：vibe coding 产物的文档常滞后于代码，一律以 `src/` 与 `tauri.conf.json` 为准。
2. **入口收敛原则**：前端所有页面路由收敛在 `App.jsx` 的 `currentNav` 三元链（812–892 行），后端所有能力收敛在 `invoke_handler!` 宏。抓住这两处即掌握全局。
3. **噪声隔离**：`node_modules/`、`src-tauri/target/`（58,615 文件，含 52,366 `.o`）占仓库 99% 体积但零认知价值，全程排除。

### 阶段 L2：页面逐个攻坚 + 真伪判定（页面层）★ 最核心

采用 **「四问法」** 对 20 个组件逐个体检，并按下述优先级排序（依 `invoke` 密度 × 代码量）：

**四问法模板**（每个组件回答 4 个问题）：

1. **数据从哪来？** — `grep "invoke("` 计数；0 次 = 高度疑似纯 UI 假页
2. **状态谁持有？** — props 来自 `App.jsx` 还是组件内 `useState`
3. **有哪些交互出口？** — 按钮/右键菜单/拖拽 handler 清单
4. **是真是假？** — 是否存在 `setInterval` 伪进度、硬编码常量数组、`mock/占位/TODO` 标记
