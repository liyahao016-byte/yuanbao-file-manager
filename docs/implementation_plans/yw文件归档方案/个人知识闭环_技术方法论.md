## 00 电梯陈述

**个人知识闭环**是一套 `Todo 完成 → 结构化归档 → Obsidian 沉淀 → 反向复用` 的**本地优先**工作流。

日常事务如洪水般涌来（P0 走查、PRD 对齐、周报、跨端需求…），完成后要么散在各种工具里查不到，要么忘了记录，两周后回看只剩"我到底做了什么"的困惑。

这套方法用**一个本地工作台 + 一个本地 HTTP 桥 + 一个 Obsidian vault**，让每天的产出自动沉淀成可回溯、可聚合、可迁移的知识资产。

| 项目   | 说明                    |
| :----- | :---------------------- |
| 版本   | v1.0 · 2026-08         |
| 特性   | 本地优先 · 零依赖      |
| 技术栈 | Node + Obsidian + macOS |

## 01 核心理念：三条设计原则

### 01 · 单一数据源

所有归档最终都是 Obsidian vault 里的 Markdown 文件。工作台只是编辑器，不持久化任何状态。断电、桥崩、换机器，数据都在磁盘上。

### 02 · 本地优先

所有服务只监听 `127.0.0.1`。不上传、不联网、不追踪。iCloud / 坚果云只做文件层同步，业务逻辑不依赖任何云 API。

### 03 · 前后端解耦

前端用任何技术栈实现（HTML / React / Swift 都行），只要能发 HTTP。换 UI 不动数据，换数据也不动 UI。

---

## 02 三层架构

> 从 UI 到磁盘只走三跳。每一层的边界就是"可替换性"——换 UI 只改第 1 层，换协议只改第 2 层，换存储只改第 3 层。

### 第 1 层 · 工作台 UI（用户视角）

- **功能**：Todo 看板 · 归档弹窗 · 随手笔记浮窗 · 设置面板 · 快捷键（`Cmd+N` / `Cmd+Enter` / `Esc`）
- **技术**：HTML · CSS · Vanilla JS · 零构建 · 双击 `index.html` 即可运行

```
↓  HTTP · JSON  ↓
```

### 第 2 层 · 本地桥 archive-bridge（Node HTTP :7733）

- **功能**：4 个接口 `/health` · `/archive` · `/notes` · `/config` · 仅监听 `127.0.0.1` · launchd 开机自启
- **技术**：Node.js 原生 `http` · 无第三方依赖 · < 300 行代码 · 崩溃自拉起

```
↓  fs.write · fs.readFile  ↓
```

### 第 3 层 · Obsidian Vault（本地知识库）

- **功能**：PARA 简化结构 `00-inbox` / `10-projects` / `20-areas` / `30-daily` / `90-archive`
- **技术**：Markdown 文件 + iCloud 同步 · Dataview 反向聚合周 / 月视图

## 03 归档数据流

> 勾选 → 归档 → 落盘 · 30 秒闭环

| 步骤 | 动作              | 说明                                   |
| :--- | :---------------- | :------------------------------------- |
| 01   | 勾选 todo         | 工作台 UI · 弹出总结面板              |
| 02   | 填 5 个字段       | 产出 · 卡点 · 下一步 · 标签 · 耗时 |
| 03   | `POST /archive` | JSON · 走`127.0.0.1:7733`           |
| 04   | 桥追加片段        | 文件不存在自动建 · 存在追加           |
| 05   | Obsidian 感知     | 自动 reindex · Dataview 立即刷新      |

### JSON Payload

```http
POST http://127.0.0.1:7733/archive
Content-Type: application/json
```

```json
{
  "date": "2026-08-28",
  "time": "18:14",
  "title": "整理todo+汇总—发给Lancy",
  "project": "语音方向",
  "priority": "P0",
  "duration": "45 min",
  "output": "14 项 P0 问题列表已整理...\n链接：https://docs.qq.com/doc/xxx",
  "blocker": "海外语音需求颜色未对齐",
  "next": "明天上午对齐海外需求",
  "tags": ["语音", "P0", "跨团队"]
}
```

### 写入的 Markdown 片段

```markdown
### ✅ 18:14 整理todo+汇总—发给Lancy
- 项目：语音方向 · 优先级：P0 · 耗时：45 min
- 关键产出：14 项 P0 问题列表已整理...
  链接：https://docs.qq.com/doc/xxx
- 卡点：海外语音需求颜色未对齐
- 下一步：明天上午对齐海外需求
- 标签：#语音 #P0 #跨团队
```

## 04 桥接口清单

> 四个 HTTP 接口，全部走本地。

| METHOD             | PATH         | 作用                               | 落盘位置                           |
| :----------------- | :----------- | :--------------------------------- | :--------------------------------- |
| `GET`            | `/health`  | 健康检查 · 前端 8s 轮询判断桥状态 | —                                 |
| `POST`           | `/archive` | 追加 todo 归档到当天 daily note    | `30-daily/YYYY/MM/YYYY-MM-DD.md` |
| `POST`           | `/notes`   | 追加随手笔记 · 800ms 防抖自动保存 | `00-inbox/quick-notes.md`        |
| `GET` / `POST` | `/config`  | 读写路径配置 · 改完立即生效不重启 | `~/.workbench-config.json`       |

### `/config` 结构

```json
{
  "vaultRoot": "/Users/xxx/Documents/vault",
  "dailyDir": "30-daily",
  "dailyPattern": "{year}/{month}/{date}.md",
  "notesFile": "00-inbox/quick-notes.md",
  "notesTimeFormat": "## {date} {time}"
}
```

> `dailyPattern` 支持 `{year}` / `{month}` / `{date}` 三个占位符，可以按你的习惯改成 `{year}-{month}/{date}.md` 之类。

## 05 PARA 简化目录

> 从 8 个一级目录减到 5 个。决策维度从"这归 30-个人管理还是 60-灵感"变成"这是项目还是领域"——判断成本从"想 5 秒"降到"想 1 秒"。

| 目录            | 用途                  | 判断标准                                         |
| :-------------- | :-------------------- | :----------------------------------------------- |
| `00-inbox`    | 未分类入口 + 随手笔记 | 想不清楚归哪就丢这，一周后再分类                 |
| `10-projects` | 进行中的项目          | 有截止日期 + 明确产出物                          |
| `20-areas`    | 长期维护的领域        | 健康 / 学习 / 兴趣 · 永远在做                   |
| `30-daily`    | 日记 / 归档总结       | 按`YYYY/MM/YYYY-MM-DD.md` 组织，工作台默认目标 |
| `90-archive`  | 已完成 / 不再相关     | 别删，扔这，日后可能翻回来                       |

### 决策流程

```
新内容
├─ 是不是日记？ ────────────────── 30-daily
├─ 是不是项目（有截止日期）？ ───── 10-projects/{项目}/
├─ 是不是长期话题？ ────────────── 20-areas/{领域}/
└─ 想不清楚 ───────────────────── 00-inbox（一周后再分类）
```

## 06 搭建步骤

> 5 步就能跑起来。
> **前置**：macOS · Node.js 18+ · Obsidian 客户端。桥无 npm 依赖，只用原生 `http` 模块。

### 1. 装 Obsidian + 建 vault

官网下载 Obsidian，创建 vault（例如 `~/Documents/vault`），vault 内建 5 个空目录：`00-inbox` / `10-projects` / `20-areas` / `30-daily` / `90-archive`。

### 2. 拷贝 workspace-app/ 到本机

把 `public/` 和 `bridge/` 两个目录整体拷到你想放的位置。前端零构建，桥零依赖，不需要 `npm install`。

### 3. cd bridge && ./install.sh

脚本自动检测 node 路径、生成 launchd plist、加载服务、设置开机自启。用 `curl http://127.0.0.1:7733/health` 验证。

### 4. 浏览器打开 index.html + 改设置

双击 `public/index.html`，左下角「设置」把 vault 路径改成你自己的，保存立即生效。

### 5. 开始用 · 跑一周看看

勾选 todo → 填总结 → 归档，感受一天下来 Obsidian 里自动长出的时间线。回头再调模版字段。

## 07 每日使用心智

> 三个场景覆盖 90% 日常。

### 场景 A · 完成一件事

1. 工作台勾选完成的 todo
2. 弹窗自动弹起
3. 填 5 字段（经常只填「产出」）
4. `Cmd+Enter` 归档
5. 右栏时间线立即出现新卡片

### 场景 B · 冒出想法

1. 按 `Cmd+N` 或点右下角浮动按钮
2. 打开笔记面板
3. 边打字边自动同步（800ms 防抖）
4. 关掉面板，Obsidian 已收到

### 场景 C · 改路径

左下角设置按钮 → 改 vault 路径 / 归档目录 / 笔记文件路径 → 保存立即生效，不用重启桥。

### 快捷键

| 键            | 动作                                  |
| :------------ | :------------------------------------ |
| `Cmd+N`     | 打开 / 聚焦随手笔记                   |
| `Cmd+Enter` | 归档弹窗中即时归档 / 笔记面板即时同步 |
| `Esc`       | 关闭浮窗 / 弹窗                       |

## 08 进阶配置与扩展

> 接入到更大的工作流。

### Obsidian Dataview 周视图

在任意 `.md` 文件里贴以下代码块，自动生成"最近 7 天完成事项"表格：

````
```dataview
TABLE without id
  file.link as "日期",
  choice(contains(file.tags, "#P0"), "🔴", "") as "P0",
  length(file.tags) as "标签数"
FROM "30-daily"
WHERE date(file.name) >= date(today) - dur(7 days)
SORT file.name DESC
```
````

### 加接口：查询已归档

桥可扩展 `GET /archives?date=YYYY-MM-DD` 读取当天已归档条目，让工作台反向展示 Obsidian 已有数据。

### 换存储：接 Logseq / Notion

只改桥的 `appendArchive` 函数即可。Logseq 一样是 Markdown 文件系统，改路径就行；Notion 需要走它的 API SDK。

### 多机同步

vault 放 iCloud Drive / 坚果云同步目录里，多台机器共用一个 vault。桥各机器独立跑，不冲突。

### 团队协作边界

本设计是**单人闭环**。团队场景推荐把归档产物同步到腾讯文档 / iWiki 供他人查阅，但工作台本身还是个人的。

## 09 FAQ 排障

**Q：桥启动失败怎么查？**
A：`cat workspace-app/bridge/bridge.error.log`。常见原因：node 不在 PATH、端口被占、`vaultRoot` 不存在。

**Q：桥端口被占了怎么改？**
A：编辑 `bridge/archive-bridge.js` 的 `PORT` 常量，同步改前端 `app.js` 的 `BRIDGE_URL`。

**Q：桥崩了会自动重启吗？**
A：launchd `KeepAlive: true` 已开启，崩了自拉起，日志追加到 `bridge.log`。

**Q：想临时禁用桥？**
A：`launchctl unload ~/Library/LaunchAgents/com.xxx.archive-bridge.plist`，或直接跑 `./uninstall.sh`。

**Q：归档写错了想撤回？**
A：Obsidian 自带 undo；实在不行手动改 daily note 就行——**它就是普通 Markdown 文件**。

**Q：数据备份？**
A：vault 已经在你磁盘里 + iCloud Drive，天然多副本。想加保险再用 Time Machine。
