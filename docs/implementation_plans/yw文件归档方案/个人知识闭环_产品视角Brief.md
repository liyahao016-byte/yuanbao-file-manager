## 01 用户痛点

> 为什么现有工具都不够？
> 通过对自己（腾讯语音方向 PM）近半年工作的复盘 + 与 5 位同事的访谈，提炼出 3 个反复出现的痛点。

### 01 · 做完就忘 · 复盘时找不到证据

Todo 勾掉之后没有留下任何"过程产物"。周五写周报时翻遍飞书 / 腾讯文档 / 微信聊天记录才能拼出一周做了什么。

> "上周三下午我到底在干嘛？——不知道，只记得开了会。"

### 02 · 工具太多 · 每个都留 30% 的信息

TAPD 有 todo、飞书有会议纪要、腾讯文档有 PRD、Obsidian 有笔记、微信有临时讨论。**没有一个地方能看到"我今天完成了什么"的全景**。

> "我的第二大脑分散在 8 个 SaaS 里，它们不通气。"

### 03 · 写总结门槛太高 · 干脆不写

Notion / Obsidian 打开就是一片空白页，让人不知道从哪写起。想留个记录还得先想模版、想标签、想放哪个文件夹——**摩擦太大，最终选择不写**。

> "知道该记录，就是懒得开另一个 App。"

## 02 产品定位

> **不是又一个 Notion。**
> 我们不做"更好的知识库"，也不做"更好的 todo 应用"。我们做的是**连接两者的最短那条线**。

> 让"完成一件事"和"沉淀这件事"之间的距离，从 5 分钟降到 30 秒。
> —— 个人知识闭环 · 产品心智

### 四条价值主张

| #  | 价值主张                      | 说明                                                                                           |
| :- | :---------------------------- | :--------------------------------------------------------------------------------------------- |
| 01 | **零摩擦归档**          | 勾选 todo 的动作自动触发总结弹窗。字段预填、标签预测、快捷键收工——90% 的场景 30 秒结束。     |
| 02 | **数据永远在你手里**    | 所有产出都是本地 Markdown 文件。不锁死在任何 SaaS，随时能带走、能 grep、能给 AI 消费。         |
| 03 | **时间线自动生长**      | 每天勾掉的事自动变成当天的 daily note。一周下来自动生成周报素材，一个月下来自动生成绩效素材。  |
| 04 | **AI-Ready 的知识资产** | 结构化的 Markdown + 标签体系天然适合喂给 LLM。为下一步 AI 自动生成日报 / 周报 / 复盘打好底座。 |

## 03 用户画像

> 谁会用它？三类高频使用人群，共同特征：**产出密集、信息多头、需要频繁回看和复盘**。

### P · 产品经理

- **标签**：跨团队协作 · 需求追踪
- **画像**：每天 30+ 条 todo，来自 PRD 评审、走查反馈、跨端需求。周报是他们最痛的场景。

### E · 技术骨干

- **标签**：代码 + Review + 会议
- **画像**：每天在 IDE / MR / 会议之间切换。绩效评审时需要证明"我这季度做了什么"，缺证据链。

### D · 独立创作者

- **标签**：自由职业 · 多项目并行
- **画像**：没有公司 SOP 的支持，全靠自己组织节奏。写作 / 播客 / 客户交付并行，最需要"个人 CRM"。

## 05 核心体验

> **30 秒完成一次归档。** 这是产品的核心链路，其余所有功能都围绕这条线打磨。

| 步骤 | 动作           | 说明               |
| :--- | :------------- | :----------------- |
| 1    | 勾选 todo      | 看板任意行的复选框 |
| 2    | 弹窗自动弹起   | 标签自动预测       |
| 3    | 填「关键产出」 | 其他字段选填       |
| 4    | `Cmd+Enter`  | 立即归档           |
| 5    | 时间线更新     | Obsidian 同步      |

**支撑设计**：

- 工作台架构 · 三层解耦，任意一层都可替换
- 数据流 · 从勾选到落盘只走 5 步

## 06 竞品对比

> 类似定位的工具都有，但没有一款专门做"todo → 沉淀"这条链路的闭环。

| 产品                   | 定位          | 本地优先       | Todo 归档闭环   | 零摩擦模版    | AI-Ready      |
| :--------------------- | :------------ | :------------- | :-------------- | :------------ | :------------ |
| **Notion**       | 全能笔记      | ✗ 云端锁定    | ✗ 需手动搭     | ✗ 页面即空白 | △ API 慢     |
| **Obsidian**     | 本地笔记      | ✓ 本地文件    | ✗ 无 todo 概念 | △ 需装插件   | ✓ 结构化     |
| **Things 3**     | Apple 系 todo | △ iCloud 锁定 | ✗ 勾完就没了   | ✗ 无总结字段 | ✗ 私有格式   |
| **飞书 / TAPD**  | 协作工具      | ✗ SaaS        | ✗ 面向团队     | ✗ 重流程     | ✗ 数据不可导 |
| **个人知识闭环** | 本方案        | ✓ 全本地      | ✓ 核心链路     | ✓ 30 秒模版  | ✓ Markdown   |

## 07 产品路线

> 从自用到产品化。当前处于 M0 阶段（个人 MVP 已跑通），下一步分三个里程碑推进。

### M0 · 已完成 —— MVP 自用 · 6 周

工作台 + 本地桥 + Obsidian 三方联动跑通，出品人自用 3 周，日均归档 5-8 条，随手笔记 3-5 条。核心链路验证通过。

### M1 · 未来 4 周 —— 小圈层内测 · 5 位种子用户

邀请 3 位 PM 同事 + 2 位技术同事内测，收集使用数据（归档频次 / 单次耗时 / 弃用率）+ 定性反馈（模版字段是否合适 / 快捷键学习成本）。

### M2 · 未来 8 周 —— 接入 AI 助手 · 自动生成日报

基于当天已归档的 todo，AI 自动生成"今日总结"初稿，用户只需审阅补充。核心杠杆：让归档产生的数据反哺产出效率。

### M3 · 未来 6 个月 —— 公开发布 · 决策点

基于 M1 / M2 数据决策：

- **A** 开源 GitHub（技术影响力）
- **B** 内部工具（腾讯内孵化）
- **C** 独立付费产品（macOS App Store）

数据说话。

## 08 风险与不确定

> 可能失败的地方。诚实地列出 3 个我自己都不确定的问题——邀请产品视角挑战。

### ?1 愿付费用户 = 高门槛技术人？

需要装 Obsidian + Node + 会用命令行的用户，天花板可能只有 1-2 万人。是否值得做成付费产品，还是应该只做开源工具？

### ?2 习惯养成的坡度多陡？

"勾完 todo 停下来花 30 秒填总结"——这个动作本身是反直觉的。3 天新鲜期过后，是否还有 30% 留存？没有真实数据支撑。

### ?3 AI Agent 时代还需要人手勾？

2026 的用户会不会觉得"我说一句 Siri，你就该知道我今天做了什么"？这个产品的核心链路可能在 24 个月内被 AI 平推。
