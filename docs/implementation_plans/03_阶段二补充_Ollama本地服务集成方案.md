# 🚀 研发搜索与AI文件管理技术实施方案 (拥抱 Ollama 生态版)

这是一个非常重要的架构转折点！既然你的系统中已经运行了 **Ollama** 并且内置了强大的 **Qwen 2.5 13B**，我们可以**大幅精简 Rust 后端的复杂度**，直接将 AI 计算下发给 Ollama 引擎。

## 为什么这是一个重大利好？

1. **极致轻量**：我们原本计划引入 `ort` (ONNX Runtime) 并将模型文件打包进应用（导致安装包膨胀 100MB 以上）。现在，应用本体大小只需不到 **10MB**，完全依赖你本地机器上已有的 Ollama 服务。
2. **统一调度**：Rust 只需要作为一个轻量级的 API 客户端，通过本地 `http://localhost:11434` 就可以完成所有的 AI 任务。

## 阶段二实施细节：Ollama 驱动的 AI 管线

根据大语言模型（LLM）和向量模型（Embedding）的不同职责，我们将架构调整如下：

### 1. AI 智能重命名 & 实体提取 (使用现有的 Qwen)
- **模型使用**：直接调用你现有的 `qwen2.5:13b`。
- **职责**：当遇到名字为乱码的文件（如 `mmexport168.jpg`, `DOC001.pdf`）时，读取文件前 1000 个字符，发送给 Qwen 提取结构化信息（如 `{甲方}-{乙方}-{合同类型}`）并返回重命名建议。
- **优点**：13B 模型的逻辑理解能力极强，完全胜任复杂文档的内容抽取。

### 2. 语义向量化 Embedding (引入轻量级 Embedding 模型)
- **注意点**：Qwen 2.5 13B 是**生成式模型**，速度较慢，不适合用来为几万个本地文件做快速的“语义打分”和“向量余弦相似度”计算。
- **方案调整**：我们将依然使用 Ollama，但你需要通过 Ollama 额外拉取一个专门用于计算特征向量的小模型，例如 **`bge-m3`** 或 **`nomic-embed-text`**。
- **流程**：后端扫描到新文件 -> 抽取文本 -> 抛给 `Ollama (bge-m3)` 接口 -> 瞬间返回一个 1024 维度的特征向量 -> 存入 `sqlite-vec` 向量数据库。
- **速度**：专门的 Embedding 模型可以在毫秒级完成段落的向量化。
