# 研发搜索与AI分类文件落地技术实施方案 (阶段一)

## 整体技术选型方案

为了实现文件监控、全文检索、向量模型推理和聚类算法，我们将整个应用升级为**前后端分离的桌面端架构**：

| 层级 | 技术选型 | 选用原因（对标调研文档） |
|---|---|---|
| **桌面外壳** | **Tauri (Rust) 或 Electron (Node.js)** | 负责文件系统监控、原生菜单、系统级拖拽。 |
| **本地数据库** | **SQLite (开启 FTS5) + sqlite-vec** | 调研文档指出本地搜索需要混合检索。FTS5 负责精确词法搜索（类似 Everything），sqlite-vec 负责存本地大模型生成的向量，实现一体化的混合检索。 |
| **嵌入模型(Embedding)** | **BGE-M3 (ONNX runtime)** | 调研文档重点推荐。多语言支持好，支持本地小显存/CPU推理（2-5ms/块），负责将文档转化为向量用于搜索和聚类。 |
| **聚类算法** | **HDBSCAN** | 文档中明确指定，适合不需要预设类簇数量、有噪声分布的本地文件标签生成。 |
| **本地LLM** | **Ollama / Llama.cpp + 轻量大模型 (如 Qwen2-1.5B/4B)** | 用于“Agentic 验证阶段”和“AI文件重命名”提取实体信息（甲方、乙方、金额、日期）。 |

## 实施阶段与架构拆解

### 阶段一：打通底层数据流 (系统与索引层)
1. **构建桌面环境**：将现有的 React 代码无缝嵌入桌面外壳中。
2. **本地文件扫描器**：编写后端服务，监控指定目录，使用系统原生 API 提取文件的元数据存入 SQLite。
3. **词法检索 (Keyword Search) 落地**：对扫描入库的文件名在 SQLite 中建立 FTS5 倒排索引，实现毫秒级的纯关键词检索。

*(最终决策：选择 Tauri Rust 作为技术底座)*
