# 智能文件夹算法与全景卡片技术架构文档 (Smart Folders Architecture)

本文档专门用于全面归档“元宝文件管理器”中**智能文件夹（Smart Folders）**系统的全套技术路径、聚类算法策略、数据流架构及前端全景卡片交互设计。

---

## 📌 1. 系统概述与设计理念

智能文件夹旨在打破传统操作系统依靠单一物理目录层级管理文件的局限，基于 **文件格式维度**、**AI 语义主题维度** 以及 **用户打包聚合维度**，为用户构建一个自动化、可多维拓展、支持高度自定义的文件聚合全景视图。

### 核心解耦目标
1. **解决数据单一占满问题**：针对工作区中含有海量截图/微信文件等干扰项的场景，通过智能停用词清洗与多维分类，防止单一格式剥夺其他主题的展示机会。
2. **多层级分类结构**：
   - **顶部固定层**：4 大基础格式分类（图片、文档、表格、媒体），固定置顶。
   - **主题与打包层**：AI 语义抽取的动态主题簇 + 用户手动打包的聚合文件夹，支持拖拽排序与个性化钉住/隐藏。
3. **综合双重下钻交互**：兼顾“就地快速预览确认”与“全视图完整文件管理”。

## 🧠 2. 后端算法与数据处理流水线 (Backend Pipeline)

### 2.1 格式大类精准聚类 (Format Micro-Clustering)
后端在执行 `get_smart_folder_stats` 时，首先读取数据库全量文件扩展名（Extension），归类为四大固定格式簇：

```rust
match ext.as_str() {
    "jpg" | "jpeg" | "png" | "gif" | "svg" | "webp" | "bmp" => img_count += 1,
    "pdf" | "doc" | "docx" | "txt" | "md" | "pages"        => doc_count += 1,
    "xls" | "xlsx" | "csv" | "numbers"                     => xls_count += 1,
    "mp4" | "mov" | "mp3" | "wav" | "m4a" | "avi" | "mkv"   => media_count += 1,
    _ => {}
}
```
- **ID 规约**：`smart_format_image`, `smart_format_document`, `smart_format_excel`, `smart_format_media`
- **标识类型**：`category_type: Some("format")`

---

### 2.2 AI 语义与 N-Gram 混合聚类算法 (Semantic & N-Gram Hybrid Clustering)

为了抽取更有价值的业务主题，算法采用以下流水线：

```
[原始文件名/内容摘要]
        ↓
 [停用词过滤 (Stopwords Cleaning)] -> 剔除 "微信", "截图", "屏幕", "00", "01" 等通用干扰词
        ↓
[N-Gram 词频与重叠率过滤] -> 抽取 candidate_clusters (频次 >= 2)
        ↓
[sqlite-vec 向量空间近邻扩展] -> 计算组内 Centroid 质心，匹配 Top-10 语义相近文件
        ↓
 [输出主题 SmartCluster] -> category_type: Some("theme")
```

---

### 2.3 AI 智能打包与主题拟名引擎 (`ollama.rs`)

当用户在收纳区点击【打包聚合】时，触发基于 Ollama (`qwen2.5:32b`) 的主题拟名引擎：

1. **信息提取**：收集收纳区所有文件的路径、名称与文本摘要（支持 DOCX/PDF 文本提取与图片 OCR 结果）。
2. **多候选生成**：构造 Prompt 要求大模型输出 **1 个最完整主名称 + 2 个精简 Tag 备选词**。
3. **离线降级方案**：若 Ollama 离线或响应超时，系统自动平滑回退为 `归档打包_YYYYMMDD_HHMM` 格式，保障 100% 成功落盘。

### 3.2 拖拽排序与持久化状态管理 (`SmartFolderCard.jsx`)

- **HTML5 Drag & Drop 拖拽**：鼠标按住主题卡片即可实时交换前后渲染位置。
- **状态持久化 (Storage Keys)**：
  - `smart_cluster_order`: 存储用户自定义排列的簇 ID 数组。
  - `smart_pinned_ids`: 存储被 📌 钉住置顶的簇 ID 数组（置顶簇在主题区头部高亮绿框显示）。

## 📁 4. 核心接口与数据结构规约

### 4.1 数据结构 (`SmartCluster`)
```rust
#[derive(Serialize)]
struct SmartCluster {
    id: String,
    name: String,
    count: usize,
    category_type: Option<String>, // "format" 或 "theme"
    path: Option<String>,          // 若为用户打包文件夹，则记录物理磁盘路径
}
```

### 4.2 Tauri Command 接口列表

| 接口名称 | 输入参数 | 返回类型 | 功能说明 |
|---|---|---|---|
| `get_smart_folder_stats` | 无 | `Result<Vec<SmartCluster>, String>` | 获取全量分类簇统计（含 4 大格式簇与主题簇） |
| `get_files_by_cluster` | `{ theme: String }` | `Result<Vec<FileItem>, String>` | 根据格式簇 ID 或主题名称查询关联文件列表 |
| `generate_smart_group_name` | `{ paths: Vec<String> }` | `Result<Vec<String>, String>` | 传入文件列表，调用 AI 归纳生成 3 个主题名称 |
| `create_aggregate_folder` | `{ paths, folderName, targetDir }` | `Result<String, String>` | 创建聚合文件夹并将暂存文件安全打包入内 |
