## 一、 亮点功能

### 1. AI 智能聚类

- **无需手动归类**：系统全自动扫描并分析全盘文件，将散乱的资产自动归集为格式速查入口（图片、文档、表格、媒体）与 9 大预设场景簇（`求职简历`、`合同协议`、`财务发票`、`方案报告`、`数据报表`、`设计素材`、`学习备考`、`影音媒体`、`代码工程`）。
- **自然语言搜索即建簇**：支持在智能文件夹输入框中输入任意自然语言主题（如“西财期末复习”、“股票分析数据”），系统基于全文本与 AI 描述摘要深度匹配全盘资产（≥ 1 匹配即成立），瞬间在首屏非钉住区域第一位置动态挂载专属簇卡片。
- **智能排序**：簇卡片根据用户实际使用频次与钉住状态智能升降排列。

### 2. 混合检索与匹配线索

- **双通道混合检索**：采用 BM25 文本精准匹配与 `sqlite-vec` 向量语义相似度的双通道融合算法，支持自然语言搜索与模糊查询。搜“求职”能自动关联匹配“简历.docx”，搜“报销”能自动关联匹配“发票.pdf”。
- **透明化匹配线索**：在搜索结果中清晰显示命中策略（`命中文件名`、`命中文档正文`、`命中图片OCR文本`、`命中语义概念`），消除传统的搜索黑盒感。

### 3. 多标签页与双视图分屏

- **多标签页管理**：支持新建 `+` 标签页、拖拽调整顺序，任何搜索操作均自动开启新标签页展示结果，完美保护原有工作上下文。
- **独立上下分屏**：上下半屏各自拥有**独立标签页栏**。用户可在上栏打开“最近文件”，下栏打开“下载目录”或“智能簇”，直接在两栏之间进行跨目录直观拖拽移动与对比管理。

### 4. 便捷收纳区

- **随手收纳**：随时将分散在各处的文件拖入右下角暂存收纳盘。
- **智能打包**：既支持用户自行命名，又支持AI命名： AI 引擎分析暂存区选中文件的公共内容特征，自动推荐精准的聚合文件夹名称（如“2026年终财务报表聚合”），并一键将文件夹打包到智能文件夹Tab方便随时使用。
- **一键导出**：收纳好的文件包一键调取本地文件路径完成导出。

### 5. 端侧隐私与极速性能

- **全本地端侧安全**：文件解析、嵌入向量计算与 SQLite 数据库索引全在用户本地机器上完成，零数据上云。
- **Rust 毫秒级性能**：基于 Tauri 2.0 + Rust 异步驱动，内存占用较传统桌面应用降低 90%，毫秒级极速响应。

  - **导出与 AI 打包**：
    - `导出至本地`：将勾选的文件批量导出至用户指定的目标文件夹；
    - `AI 命名打包`：调用 AI 分析选中文件的共同语义特征，推荐聚合文件夹名称，一键创建目录并将文件迁移入内。

### 4. 右侧预览区

- **区域定位**：文件内容快速确权与深度抽查的**内容速览窗口**。
- **核心组件与功能**：
  - **多格式原生渲染**：在不启动外部第三方软件的情况下，直接在侧边栏速览：
    - **图片**：高清大图缩放预览；
    - **PDF**：多页翻页阅读与缩略图；
    - **文档 / 代码**：纯文本、Markdown 及代码语法高亮速览；

  - **标签管理**：支持在预览面板中直接修改虚拟命名与添加命名。

### 2. 混合检索与重排序

系统的智能搜索拆解为 **离线向量建库 ➔ 实时双通道召回 ➔ 混合重排序 (RRF)** 三大严密步骤：

#### 步骤一：离线全文向量化与建库

- 系统在后台（`sync_all_embeddings`）提前将全盘文件的“标题 + 正文内容 + AI 摘要描述”提取出来，调用 Embedding 模型（如 Ollama / Nomic-Embed）转化为 768 维的浮点数向量（$\vec{v}_D$），并持久化存储在 `sqlite-vec` 本地向量数据库中。

#### 步骤二：实时双通道候选召回

当用户输入 Query $Q$（如 `“求职”`）时：

1. **实时计算 Query 向量**：将查询词 $Q$ 转化为 768 维向量 $\vec{v}_Q$；
2. **双通道并行召回 Top 50 候选**：
   - **通道 A（向量语义通道）**：计算 $\vec{v}_Q$ 与数据库中所有文件向量 $\vec{v}_D$ 的余弦相似度，筛选语义最相近的 Top 50（此时 `“简历.docx”` 被成功召回）；
     $$
     \text{CosineSimilarity}(\vec{v}_Q, \vec{v}_D) = \frac{\vec{v}_Q \cdot \vec{v}_D}{\|\vec{v}_Q\| \|\vec{v}_D\|}
     $$
   - **通道 B（FTS5 文本精准通道）**：利用 SQLite `FTS5` 倒排索引匹配文件名和标签中精确包含字面词的文件 Top 50（此时 `“求职指南.txt”` 被成功召回）。

#### 步骤三：倒数排名融合重排序

将两条通道召回的候选集按**倒数排名融合算法 (RRF)** 计算综合得分 $\text{Score}_{\text{RRF}}$：

$$
\text{Score}_{\text{RRF}}(d) = \frac{1}{k + r_{\text{FTS}}(d)} + \frac{1}{k + r_{\text{Vec}}(d)}
$$

- $r_{\text{FTS}}(d)$：文件 $d$ 在文本精确匹配中的排名名次；
- $r_{\text{Vec}}(d)$：文件 $d$ 在向量语义相似度中的排名名次；
- $k$：融合缓冲常数（系统设为 $k=60.0$）。

#### 核心优势：

- **精准度与泛化度兼备**：字面精准命中的文件排在最顶部，而“字面上不含词但语义高度相关”的资产跟随在后，彻底解决了“纯向量搜索抓不准专有名词”与“传统文本搜索搜不出语义概念”的矛盾！

### 3. 智能分类技术路径

智能文件夹分类从“资产提取”到“界面卡片自适应沉浮展示”，设计了四套对应策略：

| 阶段层级 | 核心职责与策略 | 详细技术实现说明 |
| :--- | :--- | :--- |
| **1. 数据提取策略***(Data Extraction)* | 扫描全盘路径，排除黑名单目录，提取核心特征元数据 | 抽取【扩展名 ext】+【规范文件名 lower_name】+【AI 摘要描述 ai_suggestion】+【多色 Tag 标签】 |
| **2. 多维分类策略***(Multi-Dim Clustering)* | **多通道并发归集**：<br>通道 A：后缀比对 -> 4 大基础格式入口<br>通道 B：模式匹配 -> 9 大预设场景簇<br>通道 C：自然语言 -> AI 动态自定义专属簇 | 按格式（如 jpg/png、pdf/doc）、业务词库（如简历/cv、合同/nda）及全维度 SQL 模糊查找完成文件归流 |
| **3. 门槛过滤策略***(Threshold Filter)* | **控量与防护机制**：防止低质空壳卡片刷屏干扰界面 | (1) 预设场景簇：匹配文件数大于等于 5 方自动挂载卡片；<br>(2) 搜索/自定义簇：匹配文件数大于等于 1 即成立在首屏挂载 |
| **4. 分层排序策略***(Adaptive Ranker)* | **屏效优化机制**：<br>顶层：固定钉住区<br>游离层：自适应沉浮区 | 置顶卡片优先排列 -> 新建 AI 自定义簇次之 -> 其它卡片依据历史点击频次由高到低降序沉浮 |

#### 详细技术实现拆解：

1. **数据萃取层**：通过 Rust 异步线程扫描本地磁盘，抽取每个资产文件的扩展名、规范化文件名、AI 摘要描述与标签；
2. **多维分类策略**：
   - **四大固定格式簇**：按 `jpg/png`、`pdf/doc`、`xls/csv` 等后缀聚合为 4 大固定格式入口；
   - **九大预设场景簇**：基于包含“简历/cv”、“合同/nda”、“invoice”等关键词词库提取 9 大常见场景卡片；
   - **搜索生成簇**：响应自然语言输入，全维度 SQL 模糊查找并构建对应簇，提供个性化命名与 AI 命名；
3. **过滤策略**：系统预设簇设置 `count >= 5` 展示门槛，防止大量低质卡片打扰使用；自定义生成簇设置 `count >= 1` 门槛，确保用户搜索即建簇展示；
4. **分层排序策略**：在前端 React 组件构建 `sort` 比较器，置顶钉住卡片（Pinned）排最前，新建立的 AI 专属簇紧随其后，其它卡片依据历史点击频次由高到低动态自适应沉浮，保障核心屏效。

### 4. 关键技术原理详解

1. **什么是“SQLite 多维索引”？**

   - 传统文件搜索就像在字典里按单一字母傻找。而系统在本地 SQLite 数据库中针对文件的 5 个核心维度建立了解耦的复合索引（`B-Tree Multi-Column Index`）：
     `索引维度 = [扩展名 ext + 文件名 lower_name + 正文摘要 ai_suggestion + 路径 path + 颜色标签 tags]`
   - 就像给每个文件都建立了一张**多维数字身份证**，数据库无需全盘逐行扫描，而是通过索引树在 **0.001 秒级** 瞬间锁定目标文件集合。
2. **什么是“Rust 异步分析算子”？**

   - 如果使用网页 JavaScript 在前端遍历分析全盘几万个文件，界面必定卡顿崩溃。
   - Rust 是一门追求极致性能与并发安全的语言。Rust 后端开辟独立的后台任务线程（`Tokio Async Worker`），在后台**默默运行场景归集算子**（如同时扫描是否含 `简历/cv/resume` 或 `合同/协议/contract`）。
   - **特点**：比常规语言快 20~50 倍，且完全在后台运行，**1 毫秒都不占用前端渲染时间**，保证界面永远维持 60 帧极速流畅。
3. **两者如何结合得出准确分类？**

   - **分工明确**：SQLite 多维索引负责“毫秒级快速把符合特征的数据捞出来”，Rust 异步分析算子负责“并发比对业务词库与过滤计数”。
   - **结果推送**：Rust 将计算出的精确文件数（如 `求职简历: 12`、`合同协议: 45`）组合成轻量 JSON，瞬间发送给前端界面展示，实现全自动、零感知的准确聚类！
4. **向量与正文摘要在分类中的精准分工：**

   - **预设场景分类 (如发票/合同/简历)**：优先使用数据库中的正文提取摘要与规则词库比对，速度达 0.001 秒，确保标准类型零漏检；
   - **自然语言/关键词动态建簇 (如输入“股票分析”/“期末复习”)**：**模糊 query 使用 SQLite 中的向量**，即使某个文件文件名只叫 `123.pdf`，系统通过比对正文摘要及语义向量，依然能识别出其中包含“西南财经大学期末考试”，精准拉入“期末复习资料”专属簇中！
5. **用户颜色标签与多维索引的联动闭环：**

   - 索引中的 `tags` 字段**正是用户在侧边栏或列表右键菜单中手动打标的颜色标签**（如 `orange`、`green`、`red`）；
   - 当用户为文件打上颜色标签时，算法会将颜色标签也融合进向量特征，实现用户打标也可作为搜索特征。
