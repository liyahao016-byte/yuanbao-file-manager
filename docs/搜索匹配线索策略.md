# 智能文件搜索：混合检索动态字段与线索展示联合策略规范

## 一、 设计目标与核心原则

为了让用户在复杂的混合检索场景中获得“最精简、最清晰、最具解释力”的匹配反馈，我们将底层的检索引擎意图与前端的**自适应双槽位（Slot 1 & Slot 2）**展示矩阵深度融合。

1. **意图完美承接与路由**：根据置信度矩阵，实时将检索到的最核心特征映射至对应的 UI 槽位，实现“搜其所想，见其所查”。
2. **极简视觉负载 (Max 3 Control)**：一个文件无论命中多少维度的特征，其线索总数必须由后端进行优先级截断，最多**不超过 3 条**。
3. **应出尽出与排序压制**：不再暴力剔除无明显字面线索的文件，而是赋予兜底提示，依靠向量和倒排打分的组合拳将无效幻觉沉底。

## 二、 动态字段映射矩阵与双槽位路由

基于人类记忆碎片的四大维度，当用户输入 Query 时，系统实时路由展示优先级：

| 用户搜索意图分类 | 典型 Query 示例 | Slot 1 (首选展示：短文本/高亮置信) | Slot 2 (次选展示：长文本/辅助自证) | 交互与高亮规则 (Hover展示全50字) |
| :--- | :--- | :--- | :--- | :--- |
| **关系/渠道强相关** | “小张微信发我的文件” | **线索溯源** (例: `来自：微信-小张`) | **内容摘要 / 兜底主题** | 高亮人名、渠道，点击可直接追加过滤条件 |
| **时效强相关** | “上周修改的草案” | **时间实体** (例: `✨ 命中时间：8月22日`) | **内容摘要 / 兜底线索** | 高亮时间节点 |
| **实体特征相关** | “我的护照照片”、“简历” | **实体特征** (例: `✨ 命中语义主题：证件 / 简历`) | **线索溯源 / 来源路径** | 高亮证件或主题词汇 |
| **纯语义检索** | “如何报销差旅费” | **内容摘要** (例: `✨ 正文包含：“...关于差旅报销...”`) | **实体特征 / 文档主题** | 高亮正文上下文匹配分词 |
| **(兜底) 模糊匹配** | “测试” (无精准意图) | **AI语义兜底** (`✨ 匹配线索：基于 AI 语义检索`) | (留空) | 不高亮，通过分数压制至底部 |

## 三、 线索生成优先级与提取规范 (Backend Implementation)

匹配线索的生成具有严格的自上而下的优先级。当系统从数据库（FTS+Vector）中捞出文件时，按以下优先级生成并**截断保留前 3 条**。

### [T0] 顶级优先级（高置信，对接 Slot 1）
* **时间属性匹配**：文件的更新时间命中解析时间。 -> `✨ 命中时间要求：“{解析出的标准日期}”`
* **原文完美匹配**：文件名完整包含用户 Query。 -> `✨ 文件名完全匹配：“{用户的原始搜索词}”`
* **渠道与生态**：文件物理路径包含系统渠道词（如微信/下载）。 -> `✨ 命中渠道要求：“{渠道名}”`
* **核心语义主题**：文件格式或内容命中诸如简历、发票等领域分类。 -> `✨ 命中语义主题：“{Topic关键词}”`

### [T1] 次级优先级（片段自证，对接 Slot 2）
如果未被 T0 拦截所有份额，或者进入细粒度分词检查：
1. **文件名命中** -> `✨ 文件名包含“{Token}”`
2. **用户标签命中** -> `✨ 标签包含“{Token}”`
3. **实时正文嗅探提取 (核心降级机制)**：
   * *触发条件*：当搜索词未在文件名或标签中命中时。
   * *处理逻辑*：优先在文件预生成的 AI 摘要中查找；如果 `ai_suggestion` 为空或未命中，**后端将实时读取该本地文件正文的前 1000 字符**进行嗅探。
   * *提取规则*：一旦匹配到关键词，提取该词及其前后各 15 个字符。
   * *UI 展现形式* -> `✨ 正文包含：“...{命中词及前后各15字符的上下文}... ”`

### [T2] 兜底优先级（防误杀底层兜底）
* *触发条件*：经过全面扫描，上述字面与结构化特征全部未命中（即纯粹靠 Vector 距离拉出来的关联文件，甚至实时正文中也没有该词）。
* *UI 展现形式* -> `✨ 匹配线索：基于 AI 语义与正文检索`
* *处理逻辑*：直接下发给前端。由于其在打分引擎中未获得任何 Exact Match 的提权加分，若真的是垃圾幻觉，会被排序引擎牢牢压制在列表底部。

## 四、 废弃与优化说明（Frontend Overwrite 移除）
* 彻底废除旧版中前端强行读取前 30 个字符覆盖 Snippet 的逻辑。
* 彻底废除旧版中后端对无明显特征的文件进行一刀切 Strict Guard 过滤的暴政。全面转向“应出尽出、截断线索、精准提权、排序压制”的终极混合策略。
